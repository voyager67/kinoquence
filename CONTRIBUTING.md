# Contributing

1. Open an issue describing the problem, use case and acceptance criteria.
2. Keep each pull request focused; explain non-obvious trade-offs.
3. Add tests for behavior changes and update documentation/schema/examples together.
4. Run `python -m unittest discover -s tests -v` and any relevant Remotion checks available locally.
5. Record dependency and asset licenses. Do not include credentials, copyrighted reference packs or private user material.
6. Do not state that an adapter works with a model unless the test report identifies the model/version, endpoint, settings and date.

By contributing, you agree that your code contributions are offered under the MIT license and your documentation contributions under CC BY 4.0, unless a contribution explicitly states otherwise and is accepted by maintainers.
